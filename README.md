## 📌 О проекте

**GovTech AI Dispatcher** --- локальный отказоустойчивый сервис
диспетчеризации и консультирования граждан по регламентам
государственных услуг Республики Казахстан.

Система построена на автономном RAG-пайплайне (_Retrieval-Augmented
Generation_), локальных языковых моделях и микросервисной оркестрации в
**n8n**. Чувствительные данные не должны передаваться во внешние
AI-облака: обработка текста моделями выполняется локально.

> 🎯 **Цель MVP:** быстро распознавать аварийные обращения, фиксировать
> инциденты без вызова LLM и отвечать на типовые вопросы на основе
> локальной базы нормативных регламентов.

## ✨ Ключевые возможности

- ⚡ **Fast-Path:** детерминированная обработка сообщений об авариях и
  сбоях без ресурсоёмкой генерации.
- 📚 **RAG-Path:** семантический поиск по базе регламентов с
  последующей генерацией ответа на основе найденных фрагментов.
- 🔐 **Маскирование ПДн:** обнаружение и замена ИИН, телефонов и email
  перед отправкой текста в локальные модели.
- 🧠 **Локальный AI:** embeddings и LLM запускаются через Ollama на
  собственной инфраструктуре.
- 🧭 **Guardrail Router:** разделение аварийных, справочных и
  неподдерживаемых запросов.
- 🧾 **Регистрация инцидентов:** формирование структурированного
  уведомления для последующей эскалации.
- 🌐 **Telegram-интерфейс:** приём обращений и доставка ответов через
  Telegram Bot API.
- 📴 **Out-of-Scope fallback:** если подходящего регламента нет в
  базе, система не должна придумывать сведения и предлагает обратиться
  в контакт-центр 1414.

## 🚀 Установка и запуск

### 1. Подготовьте `.env`

Создайте файл `.env` в корне проекта:

```env
# База данных — замените демонстрационные значения перед эксплуатацией
POSTGRES_USER=postgres
POSTGRES_PASSWORD=CHANGE_ME_TO_A_STRONG_PASSWORD
POSTGRES_DB=govtech_db
POSTGRES_PORT=5432

# Публичный адрес webhook — заполните после запуска Cloudflare Quick Tunnel
WEBHOOK_URL=https://your-tunnel-subdomain.trycloudflare.com/
```

> 🔐 Не используйте пароль `postgres` в рабочей среде. Не коммитьте
> `.env` в репозиторий.

### 2. Запустите инфраструктуру

Из корня проекта выполните:

```powershell
docker compose up -d
```

Проверьте состояние контейнеров:

```powershell
docker compose ps
```

### 3. Загрузите модели в Ollama

```powershell
docker exec -it govtech_ollama ollama pull qwen3.5:9b
docker exec -it govtech_ollama ollama pull bge-m3
```

Убедитесь, что модели доступны:

```powershell
docker exec -it govtech_ollama ollama list
```

### 4. Инициализируйте базу данных

Скопируйте SQL-файл в контейнер PostgreSQL:

```powershell
docker cp sql/seed_data.sql govtech_postgres:/tmp/seed_data.sql
```

Затем выполните SQL-скрипт:

```powershell
docker exec -i govtech_postgres psql -U postgres -d govtech_db -v ON_ERROR_STOP=1 -f /tmp/seed_data.sql
```

Если требуется явно указать кодировку клиента, используйте соединение с
`client_encoding=UTF8` или задайте её в параметрах `psql`. Команда `SET`
в отдельном вызове `psql` не переносится в следующее независимое
соединение.

### 5. Рассчитайте embeddings

Запустите скрипт заполнения векторных представлений:

```powershell
.\scripts\seed.ps1
```

Ожидается, что скрипт использует локальную модель `bge-m3` и сохраняет
векторы размерности 1024 в таблицу `gov_regulations` либо в структуру,
определённую схемой проекта.

### 6. Настройте Cloudflare Tunnel

В отдельном окне PowerShell запустите Quick Tunnel:

```powershell
cloudflared tunnel --url http://localhost:5678
```

1.  Скопируйте выданный HTTPS-адрес вида
    `https://<random-name>.trycloudflare.com`.
2.  Укажите его в `.env` в переменной `WEBHOOK_URL`, сохранив
    завершающий `/`, если этого ожидает конфигурация.
3.  Пересоздайте контейнер n8n, чтобы применить переменные окружения:

```powershell
docker compose up -d --force-recreate n8n
```

> ⚠️ Quick Tunnel предназначен прежде всего для разработки и
> тестирования: адрес может измениться после перезапуска. Для постоянной
> эксплуатации настройте именованный туннель, доступы и правила
> безопасности.

### 7. Импортируйте workflow в n8n

1.  Откройте `http://localhost:5678`.
2.  Перейдите в **Workflows → Import from File**.
3.  Выберите `workflows/govtech_dispatcher_v0.1.json`.
4.  Настройте учётные данные Telegram в соответствующих нодах. Токен
    бота создаётся через `@BotFather`.
5.  Проверьте URL webhook и настройки доступности Ollama/PostgreSQL из
    контейнера n8n.
6.  Активируйте workflow после прохождения тестов.

### 8. Проверьте сервисы

Полезные команды для диагностики:

```powershell
docker compose ps
docker compose logs --tail=100 n8n
docker compose logs --tail=100 postgres
docker compose logs --tail=100 ollama
```

Имена сервисов и контейнеров должны соответствовать вашему
`compose.yaml` / `docker-compose.yml`.

## 🧪 Проверка работы

### Сценарий 1 --- консультация по регламенту (RAG-Path)

**Входящий запрос**

> Привет, сколько стоит поменять удостоверение личности и сколько его
> ждать?

**Ожидаемый маршрут**

`Telegram Trigger` → `Input Data Validation` → `BGE-M3 Embeddings` →
`Retrieve Knowledge (pgvector)` → `RAG Consultant (Qwen)` →
`Send Citizen Reply`

**Ожидаемое поведение**

Ответ строится на найденном фрагменте `DOC-ID-REPLACEMENT`, содержит
доступные в базе сведения о стоимости и сроках, а также ссылку на
первоисточник, если она записана в метаданных.

> ⚠️ Значения стоимости и сроков из тестового наполнения необходимо
> сверить с актуальными официальными источниками до использования для
> реального консультирования.

### Сценарий 2 --- аварийный сбой инфраструктуры (Fast-Path)

**Входящий запрос**

> Сервер лежит в ЦОНе, не работает приём! Мой ИИН 990215300123, телефон
> +77015554433. Срочно!

**Ожидаемый маршрут**

`Input Data Validation` → маскирование ПДн →
`Guardrail Router (ветка Fast-Path)` → `Format Escalation Ticket` →
`Send Escalation Notice`

**Ожидаемое поведение**

- Сообщение классифицируется как потенциальный инцидент.
- В данные, передаваемые последующим компонентам, попадает
  обезличенный текст.
- Формируется регистрационный номер или тикет, если соответствующий
  механизм реализован.
- Вызов LLM пропускается.

Заявленная в проекте цель --- ответ менее чем за **300 мс**. Это целевой
показатель, который необходимо подтвердить нагрузочными измерениями в
конкретном окружении; он не является гарантированной задержкой.

### Сценарий 3 --- запрос вне базы знаний (Out-of-Scope)

**Входящий запрос**

> Как получить разрешение на хранение охотничьего оружия и сколько это
> стоит?

**Ожидаемое поведение**

Если в базе нет подходящего регламента, система явно сообщает об
ограничении базы знаний и предлагает обратиться в Единый контакт-центр
**1414**. Модель не должна генерировать неподтверждённые требования,
сроки или суммы.

## 🧭 Важные замечания

- Этот репозиторий описывает **MVP/проектную конфигурацию**; наличие
  перечисленных функций зависит от фактической реализации workflow,
  SQL-схемы и скриптов.
- RAG снижает риск неподтверждённых ответов, но не исключает его. В
  ответах следует показывать источники и корректно отказывать при
